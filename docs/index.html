Understand the server.

ProtoPeek is a local, single-binary protocol and network workbench for the request-to-server path. gRPC keeps schemas, streaming, metadata, trailers, and status visible; HTTP keeps methods, URLs, redirects, bodies, and phase timing visible. Separate DNS, kernel-route, consented hop, and selected private-service evidence add context without silent polling, ambient scanning, bundled network executables, or invented physical links.

TargetAdapterRequest editorNative inspector

The shared path stays small and local. The adapter owns discovery, validation, invocation, cancellation, and transport events; the inspector owns the vocabulary.

01

Define the contract

A .proto file declares services, methods, and messages with typed fields and field numbers. This schema is the source of truth for both client and server.

02

Discover via reflection

If the server has reflection enabled, ProtoPeek auto-discovers every service and method at runtime. No manual config needed.

03

Communicate over HTTP/2

gRPC uses HTTP/2 for multiplexed streams, binary framing, and flow control. Headers and trailers carry metadata the body alone cannot express.

04

Read status + trailers

The final gRPC status arrives in HTTP/2 trailers, after the payload frames. ProtoPeek keeps headers, trailers, and latency visible together.

Protocol + network workbench

A small console that keeps evidence honest

The gRPC and HTTP workbenches stay protocol-native. Network Path, selected private discovery, and topology add bounded context while keeping passive, active, inferred, imported, and manual evidence visibly distinct.

Bounded protocol discovery

Check fixed loopback candidates, opt into a literal private IP, or enter one public target. See verified gRPC, safe HTTP HEAD, or open TCP evidence honestly.

Browse proto schemas

Explore files, messages, enums, fields, and dependencies in a clean tree view before sending any request.

Compose & invoke

Pick a method, fill in the request JSON with auto-generated templates, add metadata, hit invoke. See the full response with headers and trailers.

Repeat unary checks safely

Run 2–50 real RPCs strictly in sequence with explicit deadlines, cancellation, a 60-second cap, partial evidence, separate failure classes, and honest handler-vs-console timing. Calls may mutate service data.

Observe canonical gRPC Health

Run an explicit Check or one bounded Watch stream. Keep serving status, live transitions, headers, trailers, cancellation, and final gRPC status distinct—without background polling or retry.

Send real HTTP requests

Choose method, URL, params, headers, auth, body, timeout, and redirects; cancel in flight and inspect status, body, TLS, redirect, and timing evidence.

Protocol-native evidence

See the raw gRPC story: status codes, HTTP/2 metadata, trailers, stream mode, and timing — not just the payload.

Read the selected next hop

See process-perspective source, interface, gateway or on-link state, prefix, and known metric/table values without traceroute or probe packets.

Trace a bounded Linux path

Resolve once, pin one address, authorize a fixed UDP plan, and keep per-responder source RTT and ECMP evidence. Destination median exists only for exact pinned-address replies—never the last router or per-link latency.

Inventory an authorized private scope

Application ports are exact: Quick 80/443/50051/8080; gRPC 443/6565/7000/7443/9090/50051; Web 80/443/3000/4000/5000/8000/8080/8443; Expanded 80/443/3000/8000/8080/8443/9090/50051. They may receive bounded reflection + non-following HEAD /; Expanded 22/53/445/631/1883/3306/3389/5432/6379/9100 are TCP-connect-only. A 64 KiB verbose budget retains every open-port record; shown milliseconds are full probe duration, not latency.

Keep a logical evidence map

Save immutable snapshots while preserving manual labels, tags, notes, pinned positions, groups, services, and relationships across later observations. Dirty edits require an explicit save or discard.

Import, then verify Nmap hints

Parse bounded offline XML, preserve table/probed confidence, and require a fresh ProtoPeek scan before opening gRPC or HTTP.

Secret-safe local shell

Keep request work local with target-scoped replay, re-entry for redacted metadata, bounded inactive imports, and explicit recovery that never silently replaces malformed browser data.

Shipped · Now · Soon · Later

Protocol breadth, without generic-client drift

Every capability earns native evidence, tests, and a safety boundary. Source RTT never means link latency, logical topology never means physical cabling, and XML import never means Nmap execution.

Wider network operations

Bundled Nmap execution is not planned for the core binary. Public or broader range expansion and live capture remain outside the current flow; active probes never auto-install tools or request elevation.
