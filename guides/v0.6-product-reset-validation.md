## Keyboard and appearance evidence

The browser smoke used only keyboard events for these paths:

- Tab reached Home, Inspect, Network, Publish, Files, and Settings in order; Enter activated each.
- Ctrl+K and a CDP Meta+K event opened the modal command palette with focus in Search; Escape
  closed it and restored focus to the command trigger.
- Session tabs handled Home, End, ArrowRight, and ArrowLeft with wrapping.
- Space opened the narrow drawer; forward and backward Tab wrapped inside it; Escape closed it and
  restored focus to the menu trigger.

Automated tests additionally cover command-list arrows/Enter, scan-dialog containment, route-heading
focus, and one-modal ownership. Meta+K is also locked in the UI suite, but neither the browser event
nor that test is a physical macOS keyboard run.

The browser applied all five palettes — ProtoPeek, Graphite, Nord, Solarized, and High Contrast —
in both light and dark modes at 1024px. Root attributes matched all ten pairs, no pair overflowed,
and computed main-surface text contrast ranged from 10.84:1 to 21:1. System mode changed live from
light to dark without reload, and Settings changed the active palette with correct pressed state.
Static tests separately verify the broader semantic-token contrast matrix.

Chrome DevTools emulation matched both `forced-colors: active` and
`prefers-reduced-motion: reduce`. Active navigation retained a solid system-color boundary. These
four active loader selectors computed `animation-name: none`:

- `.pp-response-spinner`;

- `.pp-evidence-loading svg`; and

This is emulation evidence, not a real Windows High Contrast or OS reduced-motion sign-off. Chrome

made from that artifact.

## Idle network and safety evidence

The source tree contains no production `setInterval`. Downloader now reads one snapshot on mount,
then refreshes only after an explicit Refresh or a mutation. Tunnels and Security remain zero-fetch
on mount, while Home, gRPC context, Network capability views, This Device, Downloader, and Settings
retain only their documented bounded same-origin initial reads.

A dedicated Vite/Chrome run visited all 16 canonical routes:

`/`, `/protocols`, `/protocols/grpc`, `/protocols/http`, `/network`, `/network/route`,
`/network/path`, `/network/local`, `/network/map`, `/network/history`, `/this-pc`, `/tunnels`,
`/downloader`, `/security`, `/settings`, and `/roadmap`.

For each route, the shell rendered, initial requests received 2.5 seconds to settle, request capture
was cleared, and the route was observed for 10.5 seconds. Across 168 seconds of observation there
were zero app API requests, zero other HTTP requests, and zero Vite HTTP requests. Five Vite HMR
WebSocket frames were retained and classified separately as development-server infrastructure.
The first Tunnels/Downloader windows overlapped a source-save HMR event, so both were repeated after
source settled and passed; the final report replaces only those contaminated windows. Development
Strict Mode can double initial mount reads, which are excluded only after the settle boundary.

The idle report is `.tmp/v0.6-final/canonical-idle-final-report.json` (11,327 bytes,
SHA-256 `E2BA07060820457399CA1EC594CA4A934F2924CD48F7BB7F009D10AC386FD163`).
Explicit benchmark/repeat deadlines and bounded CLI download, aria2 readiness, and Windows service
transition timers are operation-owned; they are not ambient browser polling.

Actual Windows evidence:

With `CGO_ENABLED=0`, compile-only `go test -run '^$' -exec='cmd /c echo' ./...` passed for
`linux/amd64`, `linux/arm64`, `darwin/amd64`, and `darwin/arm64`. The dummy executor prevents the
foreign test binaries from running on Windows; this proves compilation and build-tag selection, not
runtime behavior. Repository CI is configured with Ubuntu, macOS, and Windows runners, but no
current CI run is claimed here.

There is no real-host Linux/macOS UI, filesystem-permission, service-manager, networking, or
physical Command-key evidence in this record. The Vite browser run also had no Go API backend, so it
validates browser idleness after initial reads settle rather than successful backend response
rendering. Platform-specific unsupported/permission states remain source- and test-backed until
real-host release QA.
